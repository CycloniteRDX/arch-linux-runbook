# Arch Linux Runbook

A concise, reproducible procedure for manually installing Arch Linux on a
Lenovo ThinkPad T14 Gen 1, from the official installation medium to the first
successful TTY login.

> [!WARNING]
> This runbook contains destructive storage operations. Device names and
> partition targets must be verified on the machine being installed. Never
> copy a destructive command blindly.

## Project status

Early development. The procedure is defined through direct normal and fallback
UKI generation, but it is not yet ready to follow end to end.

## Scope

This repository covers one canonical installation path:

- UEFI firmware and GPT partitioning.
- A FAT32 EFI System Partition mounted at `/boot`.
- LUKS2 full-system encryption, excluding the EFI System Partition.
- LVM inside the LUKS2 container.
- Separate ext4 logical volumes for `/` and `/home`.
- A disk-backed swap logical volume.
- An AMD unified kernel image generated by `mkinitcpio` and `ukify`.
- `systemd-boot` as the boot menu and boot-manager integration layer.
- Secure Boot managed with `sbctl`.
- NetworkManager, a regular user, and working `sudo` access.
- First boot, LUKS unlock, and TTY login verification.

It intentionally stops at a working TTY. System hardening, maintenance,
laptop integration, applications, Niri, and user configuration belong to the
related repositories.

## Target profile

| Area | Canonical choice |
| --- | --- |
| Hardware family | Lenovo ThinkPad T14 Gen 1 AMD |
| Firmware mode | UEFI with Secure Boot capability |
| Disk label | GPT |
| EFI System Partition | 1 GiB FAT32, mounted at `/boot` |
| Encrypted storage | LUKS2 container |
| Volume management | LVM inside LUKS2 |
| Filesystems | ext4 for `/` and `/home` |
| Swap | 16 GiB LVM logical volume |
| Hibernation | Not configured |
| Initramfs tooling | `mkinitcpio` with systemd hooks |
| Kernel artifact | Unified kernel image (UKI) |
| Boot manager | `systemd-boot` |
| Secure Boot | Custom keys managed with `sbctl` |
| Network service | NetworkManager |

The complete set of assumptions, names, sizes, and acceptance criteria is in
the [canonical installation profile](docs/00-installation-profile.md).

## Writing rules

The runbook is optimized for use while installing from a TTY:

- Keep the main path linear and short.
- Show commands that are practical to type manually.
- Put warnings immediately before destructive commands.
- Use one proportionate verification after each important operation.
- Avoid shell loops, arrays, long conditionals, and required helper scripts.
- Explain only what is needed to make the next safe decision.
- Move deep explanations, alternatives, and diagnostics to the handbook.
- Do not link to a handbook guide until that guide exists.

Each installation chapter follows this shape:

1. Goal.
2. Prerequisites.
3. Commands.
4. Expected result.
5. Next step.

## Source policy

Technical decisions should be checked against the current ArchWiki and
upstream project documentation before publication. Commands must be tested on
the target profile or explicitly marked as unverified.
